# Avance de la fase 1c

Plan: [observabilidad](../superpowers/plans/2026-10-07-fase-1c-observabilidad.md).
La rama local `fase-1c`, basada en `main` en `35697af`, se integró en `main`
mediante `git merge --ff-only` hasta `8c8f617`; sin push ni despliegue.

Quedaron implementados clientes async y herramientas de solo lectura para Prometheus
(7), Alertmanager (2), Grafana (3), Loki (2), Tempo (2), Mimir (4), Datadog (6) y
New Relic (5). Cada servicio tiene activación, URL/credenciales, `verify` de una
lectura y aislamiento de errores en `IntegrationRegistry`. Las pruebas de clientes
usan `httpx.MockTransport`; no contactan proveedores.

Decisiones de diseño: ocho IDs independientes para exponer únicamente herramientas
disponibles; cuerpo HTTP máximo de 2 MiB, ventana de siete días y páginas acotadas;
Mimir reutiliza la API Prometheus; New Relic `aiIssues` usa una cabecera de opt-in
experimental y podría cambiar; Datadog metrics usa la API v1 todavía publicada,
aunque el proveedor recomienda v2. El transporte no sigue redirects y no usa proxies
implícitos del entorno (`trust_env=False`).

Pendiente de validación externa: `verify_all` contra cuentas Prometheus/Alertmanager,
Grafana/Loki/Tempo/Mimir, Datadog y New Relic configuradas con credenciales de solo
lectura. No se proporcionaron esas credenciales; estos checks están bloqueados, no
omitidos por la suite. La prueba local de Postgres está disponible y sí se ejecuta.

Revisión independiente: 70 pruebas focalizadas pasaron; detectó tres hallazgos
importantes y uno menor. Se corrigieron con pruebas de regresión: los diagnósticos de
`ValidationError` excluyen los valores de entrada de los ocho settings con secretos;
`nr_apm_errors` convierte los segundos de la tool a milisegundos de NRQL; `nr_entities`
conserva `nextCursor` y acepta el cursor de continuación; las cabeceras HTTP no ASCII
producen un error seguro. La paginación y la unidad temporal siguen el contrato
documentado por New Relic.
