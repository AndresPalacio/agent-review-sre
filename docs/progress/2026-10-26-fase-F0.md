### Modelo local

- `llm/models.py`: defaults `ollama` con `llama3.2:3b` en los cuatro roles. `provider_kwargs` envía
  `base_url` (`OLLAMA_BASE_URL`), `num_ctx` (`LLM_NUM_CTX`, 8192) y el timeout por `client_kwargs`,
  porque `ChatOllama` 1.1.0 no acepta `timeout` ni `max_retries`. Los otros proveedores siguen recibiendo
  `timeout` y `max_retries`.
- `build_chat_model` y `parse_model_spec` (solo el primer `:` separa, así `ollama:llama3.2:3b` funciona)
  son ahora el único camino para construir modelos. `evals/runner._chat_model` y `work/graphs._model`
  los usan, de modo que las evals y el piloto con Ollama reciben el mismo endpoint y la misma ventana.
- `llm/structured.py`: `structured_call(model, schema, prompt, payload, fallback)` baja por tres
  escalones: salida nativa (`json_schema` en Ollama, tool calling en el resto), respuesta en texto
  pedida como JSON y analizada con `extract_json`, y por último el `fallback` determinista, que recibe
  el motivo. `StructuredResult.degraded` marca el último caso. Nunca lanza por fallos del modelo o de
  parsing; la cancelación sí se propaga.
- `extract_json` es el porte de `extract_json_from_response` de ai-hedge-fund, con un arreglo: las
  llaves dentro de strings JSON ya no rompen el balanceo.
- Dependencia `langchain-ollama>=1.1.0,<2` (trae `ollama` 0.6.3).
- `.env.example`: `LLM_PROVIDER=ollama`, `OLLAMA_BASE_URL=http://localhost:11434`, `LLM_NUM_CTX=8192`.
  El default del código sigue en `anthropic`; el que copia `.env.example` corre en local sin key.

## Spike con llama3.2:3b

`tests/spikes/test_ollama_structured.py` (marcador `ollama`) es opcional, como las pruebas de Postgres:
corre solo con `FIN_GRAPH_TEST_OLLAMA_URL` y se omite si el servidor o el modelo faltan. Así el gate
diario no depende de un LLM no determinista.

```powershell
$env:FIN_GRAPH_TEST_OLLAMA_URL = "http://localhost:11434"
uv run pytest tests/spikes/test_ollama_structured.py -m ollama
```

| Medida | Resultado observado |
|---|---|
| Primera corrida (carga del modelo con `num_ctx` 8192) | Pasa, 70 s |
| Dos llamadas en caliente | 5.8 s y 5.2 s, ambas `native`, sin errores |
| `/api/ps` | `llama3.2:3b`, `context_length` 8192: la ventana se aplica |
| Calidad | JSON válido, pero `confidence: 0` con señal `bullish`, y llama "relativamente bajo" a un D/E de 1.8 |

La calidad confirma la decisión del plan: el cálculo financiero es determinista (`domain/quant`, F1) y el
LLM solo interpreta scores ya calculados. La señal y la confianza deben salir de los scores cuando el
modelo las contradiga.
