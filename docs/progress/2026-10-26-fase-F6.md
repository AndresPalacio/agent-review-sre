# Progreso F6: API financiera, señales, gateways y scheduler de mercado

Plan: transformación SRE → finanzas, fase F6 (superficies remotas y automatización).

- Estado: F6 completa y validada localmente.
- Seguridad operativa: el servidor solo ejecuta órdenes en el broker paper y ninguna tarea
  programada coloca órdenes.

## API y persistencia

- `POST /v1/analyses` sustituye a investigaciones; estado, explicación, SSE, historial y
  reanudación conservan el mismo modelo durable de ejecución.
- `POST /v1/signals/{tradingview,price_alert,generic}` recibe señales con autenticación
  fail-closed. Cada fuente usa `X-Fin-Webhook-Token`, HMAC SHA-256 en `X-Fin-Signature` o,
  solo para TradingView, un token dentro del JSON que se elimina antes del análisis.
- La deduplicación y las rutas de entrega pasan a `SIGNAL_DEDUPE_MINUTES` y
  `SIGNAL_DELIVERY_ROUTES`; la fuente forma parte del fingerprint.
- `POST /v1/orders`, `POST /v1/analyses/{thread_id}/orders`, consulta de pendientes,
  aprobación, cancelación y liquidación usan el grafo `orders` y el libro paper persistido.
  `GET /v1/portfolio` presenta efectivo, garantía, posiciones, P&L abierto y valor neto.
- La API vuelve a validar cotización, deriva, horario, cartera y límites al ejecutar. Las
  decisiones se vinculan al interrupt exacto y se auditan sin guardar los argumentos.
- La migración Alembic `0012_finance_names` renombra tablas, índices y restricciones SRE sin
  perder los datos existentes. Los checkpoints y ejecuciones de acciones del namespace
  legado `remediation:*` se eliminan cuando vence su hilo; una regresión cubre ese caso.

## Chat y gateways

- `RemoteChatSession` usa `/analiza`, `/v1/analyses` y `/v1/orders`; ya no depende de las
  rutas remotas de investigación o remediación.
- Slack y Telegram reciben solicitudes financieras, publican reportes de análisis y ofrecen
  botones sobre órdenes paper. El inbox durable, la deduplicación, los locks y la allowlist
  de aprobadores se mantienen.
- Un botón vencido, repetido o asociado a otro interrupt no puede ejecutar una orden. El
  rollback, si el grafo lo propone, requiere una aprobación nueva.

## Scheduler

- `market_watch` evalúa de forma determinista movimiento diario, drawdown y pico de
  volatilidad. Un disparo inicia un análisis deduplicado y nunca una operación.
- `portfolio_digest` resume la cartera paper y sus órdenes en cola.
- `thesis_review` cierra tesis antiguas contra la cotización actual y actualiza el track
  record; `watch_digest` resume las comprobaciones del último día.
- Retención y expiración recorren los namespaces `analysis`, `chat` y `orders`, además de
  limpiar el namespace legado `remediation` mientras todavía pueda existir en una base
  migrada.

## Compatibilidad y documentación

- El harness y el script de aceptación ejercitan el grafo financiero y `/v1/analyses`.
- `.env.example` y la documentación operativa usan los nombres, cabeceras y rutas de F6.
- La consola React sigue siendo la superficie SRE legada y no es compatible con esta API;
  su migración está reservada para F8. Los módulos SRE que aún sirven pruebas históricas se
  retiran en F9.
