## Alcance y decisiones

React + Vite + TypeScript + Tailwind en `web/`; UI en español, accesible y adaptable a móvil. FastAPI sirve el build incluido en la imagen Docker. La API existente continúa siendo la autoridad de permisos y ejecución.

Conservar todos los cambios locales del cierre de fase 6. Trabajar en la rama actual; no publicar, fusionar ni modificar opensre. Las investigaciones siguen siendo de lectura; las remediaciones se preparan explícitamente y requieren aprobación. Las API keys viven en memoria del navegador, nunca en URL ni almacenamiento persistente. Sin proveedores externos en las pruebas.

## Contratos compartidos

- `GET /v1/session` devuelve `{role}` autenticado como viewer.
- El detalle de investigación añade `plan`, `findings`, `evidence`, `diagnosis`, `verification`, `actions`, `errors` saneados a `run`, `report`, `alert`.
- Los resultados de chat/remediación que incluyen `requests` añaden `approval_ids: string[]` con los IDs de los interrupts en el mismo orden. El SSE `approval` los incluye. Los POST de aprobación aceptan `approval_ids` opcional por compatibilidad; si se proporciona, se compara exactamente bajo el lock y se rechaza lo obsoleto con 409. La UI siempre lo envía.
- `GET /v1/chat/threads/{id}` añade `messages: {role: 'user'|'assistant', text: string}[]`, sólo contenido público sin herramientas ni secretos.
- `GET /v1/remediations/actions` devuelve `[{name, schema, rollback}]` desde el catálogo registrado, autenticado como operator. Declarar antes de la ruta dinámica. `create_app` acepta `action_catalog` opcional y lo comparte con el grafo de producción; fixtures inyectan el mismo catálogo.
- `GET /v1/remediations/{id}` añade `result` y `rollback` saneados.
- `create_app(ui_dir: Path | None = None)` sirve por defecto `server/static` si existe, sin capturar rutas `/v1`, `/health`, `/ready`, `/docs`, `/openapi.json`; rutas SPA explícitas o fallback seguro; assets ausentes devuelven 404. El build Vite produce `src/fin_graph/server/static`.
- SSE usa fetch con X-API-Key, AbortController, parsing incremental UTF-8, CRLF, multiline data e IDs; reconexión de investigaciones con Last-Event-ID sin duplicar ni reejecutar POST de chat.
